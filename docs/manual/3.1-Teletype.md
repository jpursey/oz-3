# Teletype

A port that writes text to the host, for a machine without a screen.

### Wiring and settings

The teletype is wired to one port, and has no interrupt or memory (see [Wiring and settings](3-Devices.md#wiring-and-settings)).

| Setting       | Default | What                                                                    |
| ------------- | ------- | ----------------------------------------------------------------------- |
| `baud`        | 0       | Bits a second, 10 to a character, or 0 to print as fast as cores write  |
| `buffer_size` | 4096    | The characters the teletype holds until the host takes them: at least 4 |

### Writing

* **Writing:** Each word written to the port is two packed characters, the low byte first, and a zero byte is skipped. So a single character is written as itself (`'A'` is `0041h`), and a packed string, as the assembler writes `"..."` strings, is sent straight from memory with `OUTR`.
* **Dwords:** A dword written to the port is two words, word 0 first, so `OUTR.ID` writes a packed string in half as many executions as `OUTR.IW`. The teletype clears word 1 once it takes it, so a word written after a dword isn't followed by the dword's characters again.
* **Taking:** The teletype takes what is written as soon as the port's status is set (by `OUTS`, `OUT`, or `OUTR`), the cycle after the store, and clears the status, so the next `OUTS` succeeds. An `OUTR` of a packed string runs to its end without stopping: an `OUTR.IW` of 3 words takes 27 cycles, and an `OUTR.ID` of 3 dwords 33.
* **Characters** are 7-bit ASCII: the eighth bit of each byte is dropped (it was a teletype's parity bit), and a byte that is then 0 is skipped. Control characters are sent as they are, and the host does what a terminal would with carriage return (`0Dh`), line feed (`0Ah`), backspace (`08h`), and bell (`07h`).
* **Baud rate:** A teletype may have a baud rate. Then it is busy printing what it took for 10 bits a character (a start bit, 8 data bits, and a stop bit), and takes nothing more until it is done. The port holds one more write meanwhile, and then its status stays set: `OUTS` fails, and `OUTR` stops early. There is no interrupt for "ready", as the baud rate is fixed for a machine, so a program paces itself to it, or loops on `OUTS`. At 1 MHz, 9600 baud is 1041 cycles a character, and 300 baud 33,333.
* **A full host buffer:** The host takes the text as it can, and the teletype holds up to `buffer_size` characters until it does. Once that is full, the teletype takes nothing, and the port's status stays set, as if it were busy.
* **Reading** the port isn't the teletype's business: a core that reads it gets whatever is there, and clears the status, which loses a word not yet taken.
