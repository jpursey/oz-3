# Default Instruction Set

This is the reference for the OZ-3 default instruction set, which every OZ-3 core runs unless it is given an instruction set of its own (see [Specifications](2-Specifications.md)). It is written in [microcode](2.1-Microcode.md), in `oz3/instructions/default_instruction_set.izm` (see [Instruction Set Source](2.3-Instruction-Set-Source.md)), and every cycle count here comes from that microcode.

### Conventions

#### Instruction names

Each instruction is a family of variants, and each variant has its own name, made from the instruction and a suffix (`ADD.W`, `ADD.D`, `ADD.S`). The suffixes are:

| Suffix        | Meaning                                                                               |
| ------------- | ------------------------------------------------------------------------------------- |
| `.W`          | Word (16-bit) operation on a `<reg>`                                                  |
| `.D`          | Dword (32-bit) operation on a `<dreg>`                                                |
| `.DW`         | Dword register with a word value (`MUL.DW`, `DIV.DW`, `MOD.DW`)                       |
| `.S`          | Special register: `SP` (`ADD.S`), or `BC`, `BS`, `BD`, `BE`, `SP`, and `FP` (`MOV.S`) |
| `.LW` `.LD`   | Load a word or dword into a register (`MOV`, `MVQ`)                                   |
| `.SWR` `.SDR` | Store a word or dword register to memory (`MOV`)                                      |
| `.SWV` `.SDV` | Store a word or dword integer to memory (`MOV`)                                       |
| `.RW` `.RD`   | Port number in a register, moving a word or a dword (port instructions)               |
| `.IW` `.ID`   | Port number as an immediate value, moving a word or a dword (port instructions)       |
| `.I` `.R`     | Interrupt (`INTC`) or port (`TSTP`) as a value, or in a register                      |
| `.A`          | Also pops a number of words before returning (`RET`, `RETC`, `IRT`, `IRTC`)           |

Instructions without variants (`NOP`, `HALT`, `JP`, and so on) have no suffix.

Each name has its own opcode, the high byte of its code word, which the variant tables show. Rows with the same name share an opcode, and are told apart by the code word's low byte, which also holds any registers and small values (see [OZ-3 Instruction Definition](2.1-Microcode.md#oz-3-instruction-definition)).

Programs depend on these code words, so they never change: an instruction keeps its opcode, and its variants keep their code words.

Any other code word is undefined, and a program must not use one: what it does is unspecified. An undefined code word may become valid in two ways:
- The default instruction set gains new instructions, which are only ever added after the last opcode (`0x92`).
- A [coprocessor](2-Specifications.md#coprocessors) adds opcodes of its own.

#### Operands

| Operand               | Meaning                                                                                  |
| --------------------- | ---------------------------------------------------------------------------------------- |
| `<reg>`               | A word register: `R0` to `R7`                                                            |
| `<dreg>`              | A dword register: `D0` to `D3` (`D0` is `R1:R0`, with `R0` the low word)                 |
| `<integer>`           | A word value (a dword value for dword variants), held in the words after the code word   |
| `<0..31>` and similar | A small unsigned value, held in the code word itself, so it costs no extra word or cycle |
| `<port>`              | A port number, held in the word after the code word (see [Ports](#ports))                |
| `<word-address>`      | A word in memory, in one of the [address forms](#address-forms)                          |
| `<dword-address>`     | A dword in memory, in one of the [address forms](#address-forms)                         |
| `<condition>`         | A [condition](#conditions) on the status flags                                           |
| `<flags>`             | A [flag mask](#flag-masks)                                                               |

Where an operand is a value (the second operand of `ADD`, the address of `JP`, the port of `IN.RW`), a register operand uses the value in the register, and an address operand uses the value in memory. For instance, `JP R1` jumps to the address in `R1`, and `JP (R1)` jumps to the address stored in memory at `R1`.

Dwords are stored in memory low word first, at the lower address. Arithmetic wraps at 16 bits (32 bits for dwords), so an offset or relative address of `0xFFFF` is -1.

#### Address forms

A memory operand is written in parentheses for a word, and in square brackets for a dword. Each form names the memory bank it reads or writes:

| Word form  | Dword form | Address                  | Memory bank | Extra words |
| ---------- | ---------- | ------------------------ | ----------- | :---------: |
| `(Rn)`     | `[Rn]`     | `Rn`                     | `Rn`'s bank |      0      |
| `(Rn + n)` | `[Rn + n]` | `Rn` plus the offset `n` | `Rn`'s bank |      1      |
| `(SP)`     | `[SP]`     | `SP`                     | `STACK`     |      0      |
| `(SP + n)` | `[SP + n]` | `SP` plus the offset `n` | `STACK`     |      1      |
| `(FP)`     | `[FP]`     | `FP`                     | `STACK`     |      0      |
| `(FP + n)` | `[FP + n]` | `FP` plus the offset `n` | `STACK`     |      1      |
| `S(n)`     | `S[n]`     | `n`                      | `STACK`     |      1      |
| `D(n)`     | `D[n]`     | `n`                      | `DATA`      |      1      |
| `E(n)`     | `E[n]`     | `n`                      | `EXTRA`     |      1      |

`Rn` is any word register (also for a dword, as it holds the address), and its bank is the one the [register is associated with](2-Specifications.md#registers): `DATA` for `R0` to `R3`, `EXTRA` for `R4` and `R5`, and `STACK` for `R6` and `R7`. Every address is relative to its bank's base register (`BS`, `BD`, or `BE`). A program can write a label in `S(n)`, `D(n)`, or `E(n)`, which the assembler checks is in the segment with that bank's role, and encodes as the label's address from the base register, even for `BS`, which is at the end of the stack segment (see [Addresses](2.5-Program-Source.md#addresses)).

The block, compare, and repeating port instructions (`MVI`, `CPI`, `INR`, and so on) take only the `(Rn)` form (`[Rn]` for dwords), and step the register as they go.

#### Instruction size

An instruction is a code word, followed by one word for each `<integer>` (two for a dword integer), and one word for each address form that has `n` in it. When an instruction has both an address and an integer (`MOV.SWV`, `MOV.SDV`), the address's word comes first. The port number of the `.IW` and `.ID` port variants and `TSTP.I`, and the interrupt of `GETI`, `SETI`, and `INTC.I`, take one word each.

`IP` is past the whole instruction before it runs, so a relative address (`JPR`, `JCR`, `JDR`, `CALLR`) is relative to the next instruction, and `CALL` pushes the address of the next instruction. A program writes their `<integer>` as the address to jump to, which the assembler encodes as its offset from the next instruction (see [Value types](2.3-Instruction-Set-Source.md#value-types)), so `JPR @loop` jumps to `@loop`. A relative address in a register or in memory is still an offset, which is added to `IP` unchanged. The assembler checks that a label a jump or call goes to, as its `<integer>`, is in the code segment (see [Addresses](2.5-Program-Source.md#addresses)).

#### Cycles

Each instruction gives its range of cycles, and each variant gives its own. A range covers every input, including the cheap cases: a branch or return not taken, a divide by zero, or a port that isn't ready. Where the cycles depend on a value (shifts, rotates, bit operations, multiplies, and `RST`), the description says how.

Every instruction takes at least 3 cycles to fetch and decode its code word. For an address variant, the range runs from the forms without an offset, which cost the least, to the forms with one, which cost the most. Most instructions that read a value (such as `ADD`, `CMP`, `PUSH`, and `CALL`) pay these extra cycles over the register form:

| Value form                                  | Word | Dword |
| ------------------------------------------- | :--: | :---: |
| `<reg>` or `<dreg>`                         |  0   |   0   |
| `<integer>`                                 |  1   |   2   |
| `(Rn)`, `(SP)`, `(FP)` (`[...]` for dwords) |  2   |   3   |
| `S(n)`, `D(n)`, `E(n)`                      |  3   |   4   |
| `(Rn + n)`, `(SP + n)`, `(FP + n)`          |  4   |   5   |

The ranges assume no lock contention. Waiting for a memory bank, port, or core that something else holds (see [Synchronization](2-Specifications.md#synchronization)) adds cycles without bound. Starting an interrupt handler after an instruction takes 3 more cycles (see [Interrupts](2-Specifications.md#interrupts)).

The repeating instructions (`MVIR`, `MVDR`, `CPIR`, `CPDR`, `INR`, and `OUTR`) handle one word (or dword) each time they run, and then run again until they are done, so interrupts are handled between words. Their cycles are for each execution ("each" in the tables). `R7` is their count, so none of them can use it as an address, or (for `INR` and `OUTR`) as a port register.

Where an instruction can't use a register, the assembler rejects it (see [Register rules](2.3-Instruction-Set-Source.md#register-rules)). A code word with one still runs, as the instruction describes, but no program can write it as an instruction.

#### Flags

Each instruction shows its effect on each of the `Z`, `S`, `C`, and `O` status flags (see [Flags](2-Specifications.md#flags)):

| Mark | Meaning                                                      |
| :--: | ------------------------------------------------------------ |
| `X`  | Set or cleared by the instruction                            |
| `0`  | Always cleared                                               |
| `1`  | Always set                                                   |
| `-`  | Unchanged                                                    |
| `?`  | Set, cleared, or toggled as the instruction's flag mask says |

The `I` flag is changed only by `EI`, `DI`, and returning from an interrupt (`IRT` and `IRTC`).

#### Conditions

A `<condition>` tests one status flag. A program writes it by name, such as `JC Z, @done`, using the `Condition` [named values](2.3-Instruction-Set-Source.md#named-values):

| Condition | Value | True when    |
| --------- | :---: | ------------ |
| `NZ`      |   0   | `Z` is clear |
| `NS`      |   1   | `S` is clear |
| `NC`      |   2   | `C` is clear |
| `NO`      |   3   | `O` is clear |
| `Z`       |   4   | `Z` is set   |
| `S`       |   5   | `S` is set   |
| `C`       |   6   | `C` is set   |
| `O`       |   7   | `O` is set   |

#### Flag masks

A `<flags>` mask selects any of the status flags: `Z` is 1, `S` is 2, `C` is 4, and `O` is 8. A program writes the flags by name, combined with `|`, such as `CLRF Z | C`, using the `Flags` [named values](2.3-Instruction-Set-Source.md#named-values). It can't select `I`, which has `EI` and `DI` instead.

### Control

#### NOP

| Cycles |  Z  |  S  |  C  |  O  |
| :----: | :-: | :-: | :-: | :-: |
|   3    |  -  |  -  |  -  |  -  |

Does nothing.

| Opcode | Variant | Cycles |
| :----: | ------- | :----: |
| `0x00` | `NOP`   |   3    |

#### HALT

| Cycles |  Z  |  S  |  C  |  O  |
| :----: | :-: | :-: | :-: | :-: |
|   4    |  -  |  -  |  -  |  -  |

Puts the core into the idle state. Interrupts are still handled, but the core stays idle until it is reset, or another core starts it with [RST](#rst). Another core's [WAKE](#wake) only runs the `HALT` again, as `HALT` leaves `IP` on itself.

| Opcode | Variant | Cycles |
| :----: | ------- | :----: |
| `0x01` | `HALT`  |   4    |

#### WAIT

| Cycles  |  Z  |  S  |  C  |  O  |
| :-----: | :-: | :-: | :-: | :-: |
| 3-65535 |  -  |  -  |  -  |  X  |

Puts the core into the wait state for at least the number of cycles in the register, counting from the start of the `WAIT`. A `WAIT` takes at least 3 cycles, so 0 to 3 all take 3. Interrupts are still handled during the wait, but an interrupt handler can't `WAIT` itself.

When the `WAIT` completes, the register is set to the number of cycles it took beyond those asked for, which may be more than none if an interrupt was handled or the core was locked, and the `O` flag is cleared. When it doesn't, the register is unchanged, and `O` is set, so a program can tell whether the register is meaningful:
* A `WAIT` in an interrupt handler that interrupted a `WAIT` fails at once.
* A `WAIT` ended early by [WAKE](#wake) doesn't complete. If an interrupt handler interrupted the `WAIT`, `O` is set when the handler returns to it.
* A `WAIT` with the notify flag (`N`) set, by a `WAKE` that came while the core was running, clears `N` and ends at once, as a `WAIT` ended by `WAKE` does. A `WAIT` that fails leaves `N` as it was. [CLRN](#clrn) clears `N` without waiting.

A `WAIT` ended by [RST](#rst) of `CODE` also leaves its register unchanged, but `RST` clears the flags for the new program.

| Opcode | Variant      | Cycles  |
| :----: | ------------ | :-----: |
| `0x02` | `WAIT <reg>` | 3-65535 |

### Bits and flags

The bit instructions take a bit position from a register, or as a value in the code word. A position from a register costs about 2 cycles more for each position, up to 15 for a word. Compares as [CMP](#cmp) does, but with the bytes of each word of both the register and the value swapped first. Neither is changed. Packed text holds its first character in the low byte, so `CMPT.W` compares two words of packed text in reading order: `C` is set if the register's two characters come first.

`CMPT.D` swaps each word's bytes on its own, and leaves the words where they are, so the high word is compared first, as for `CMP.D`. For packed text stored low word first, the high word holds the later two characters, so a dword compares the characters in the order 3, 4, 1, 2.

### Ports

The port instructions take the port number from a register (`.RW`, `.RD`, and `TSTP.R`) or as a value in the word after the code word (`.IW`, `.ID`, and `TSTP.I`). A port number is 0 to FFh for one of the processor's ports, or 100h to 10Fh for one of the running core's [mailboxes](2-Specifications.md#mailboxes): `100h + n` to send to core `n`, and `108h + n` to receive from it. Any other port number is a port that doesn't exist. The word variants move one word of the port. The dword variants move both, word 0 as the low word and word 1 as the high word. See [Ports](2-Specifications.md#overview) for how a port's words and status work.

| :-------: | :-: | :-: | :-: | :-: |
| 6-11 each |  -  |  X  |  -  |  -  |

Reads up to `R7` words (or dwords) from a port, storing them at the address in the address register (in the bank that register is associated with), and stepping the register past each one. A value is read only if the port status is set, as for [INS](#ins), and `R7` is decremented for each one, so it is left at the number *not* read.

It is done when `R7` is 0, which sets the `S` flag, or when the port status isn't set, which clears it.

If `R7` is 0, nothing is read, and it takes 6 cycles (7 for `INR.IW` and `INR.ID`). If the port status isn't set, it takes 7 cycles for `INR.RW`, 8 for `INR.IW` and `INR.RD`, and 9 for `INR.ID`.

Neither register can be `R7`, the count, and for `INR.RW` and `INR.RD`, the port and address registers must be different. A code word with them still runs, decrementing `R7` before it is used, and stepping the address register even when it is also the port.

| :----: | ------------------------ | :----------: |
| `0x79` | `INR.RW <reg>, (<reg>)`  |  8 per word  |
| `0x7A` | `INR.IW <port>, (<reg>)` |  9 per word  |
| `0x7B` | `INR.RD <reg>, [<reg>]`  | 10 per dword |
| `0x7C` | `INR.ID <port>, [<reg>]` | 11 per dword |

#### OUTR

|  Cycles   |  Z  |  S  |  C  |  O  |
| :-------: | :-: | :-: | :-: | :-: |
| 6-13 each |  -  |  X  |  -  |  -  |

Writes up to `R7` words (or dwords) to a port, loading them from the address in the address register (in the bank that register is associated with), and stepping the register past each one. #### TSTP

| Cycles |  Z  |  S  |  C  |  O  |
| :----: | :-: | :-: | :-: | :-: |

### Cores

#### RST

| Cycles |  Z  |  S  |  C  |  O  |
| :----: | :-: | :-: | :-: | :-: |
| 11-94  |  -  |  -  |  -  |  -  |

Resets some of a core's memory banks, and the registers that go with them. The core is given as a value from 0 to 7 in the code word, as `SELF` (the running core), or in `R2` (0 to 7, or -1 for the running core). If the core doesn't exist, nothing changes.

The bank mask (0 to 15, in the code word) selects which banks to reset, and `R3` holds the new banks, laid out as in the `MB` register. A program writes the mask by name, combined with `|`, such as `RST 2, CODE | STACK`, using the `Banks` [named values](2.3-Instruction-Set-Source.md#named-values), each the value of its bit (`CODE` is 1, `STACK` 2, `DATA` 4, and `EXTRA` 8). For each bank in the mask:

| Bit | Bank    | The core's registers                                                    |
| :-: | ------- | ----------------------------------------------------------------------- |
|  0  | `CODE`  | `BC` is set to this core's `R4`, `IP` to zero, and `R0` and `R1` copied |
|  1  | `STACK` | `BS` is set to this core's `R5`, and `SP` and `FP` to zero              |
|  2  | `DATA`  | `BD` is set to this core's `R6`                                         |
|  3  | `EXTRA` | `BE` is set to this core's `R7`                                         |

Resetting `CODE` starts a new program on the core, so it also:

* Clears all 32 of the core's interrupt handlers, so none is called until the new program sets its own.
* Clears the core's status flags, `ZSCOI`, so interrupts are disabled. For `SELF`, these are the flags `RST` ends with.
* Starts the core running from its new `IP`, if it was halted or waiting. Otherwise, as for [WAKE](#wake), it sets the core's notify flag (`N`), so the new program's first `WAIT` ends at once.

A `WAIT` the core was in is ended without completing. As the status flags are cleared, nothing shows that it didn't complete, even if the new program starts right after it, so `O` can't be read as the `WAIT`'s result. To continue from a `WAIT`, use [WAKE](#wake).

It keeps the core's pending interrupts, and its trap flag (`T`). A pending interrupt with no handler is dropped once the new program enables interrupts.

The cost depends on the banks: 11 cycles with none (12 for `SELF`), and 73 more for `CODE` (most of it clearing the handlers), 5 for `STACK`, and 2 each for `DATA` and `EXTRA`.

| Opcode | Variant                   | Cycles |
| :----: | ------------------------- | :----: |
| `0x89` | `RST <0..7>, <bank-mask>` | 11-93  |
| `0x89` | `RST R2, <bank-mask>`     | 11-93  |
| `0x89` | `RST SELF, <bank-mask>`   | 12-94  |

#### INTC

| Cycles |  Z  |  S  |  C  |  O  |
| :----: | :-: | :-: | :-: | :-: |
|  3-5   |  -  |  -  |  -  |  -  |

Raises an interrupt on a core, which handles it as for [INT](#int): after the instruction it is running, if its interrupts are enabled. A waiting or halted core handles it too, and then goes back to waiting or idle. Only the low 5 bits of the interrupt are used. The core is given as for [RST](#rst): a value from 0 to 7 in the code word, `SELF` (the running core, as `INT` does), or `R2` (0 to 7, or -1 for the running core). If the core doesn't exist, nothing happens.

`INTC` is how one core signals another, such as to call an operating system running on another core. It changes nothing the core is working on, and a core with no handler for the interrupt drops it. Cores pass data through memory, ports, and their [mailboxes](2-Specifications.md#mailboxes).

| Opcode | Variant                    | Cycles |
| :----: | -------------------------- | :----: |
| `0x8B` | `INTC.I <0..7>, <integer>` |   4    |
| `0x8B` | `INTC.I R2, <integer>`     |   4    |
| `0x8B` | `INTC.I SELF, <integer>`   |   5    |
| `0x8C` | `INTC.R <0..7>, <reg>`     |   3    |
| `0x8C` | `INTC.R R2, <reg>`         |   3    |
| `0x8C` | `INTC.R SELF, <reg>`       |   4    |

#### WAKE

| Cycles |  Z  |  S  |  C  |  O  |
| :----: | :-: | :-: | :-: | :-: |
|  4-5   |  -  |  -  |  -  |  -  |

Ends a core's [WAIT](#wait), or starts it running from its current `IP` if it is idle. If the core is handling an interrupt that interrupted a `WAIT`, that `WAIT` is ended too, so the interrupt returns to the instruction after it. A `WAIT` ended this way doesn't complete, so its register is unchanged, and the core's `O` flag is set (when the interrupt returns to it, for a `WAIT` an interrupt handler interrupted). The core is given as for [RST](#rst). If the core doesn't exist, nothing happens.

`WAKE` answers a core that is waiting for another, and leaves it where it is: unlike `RST`, it doesn't move `IP`. A core idle from [HALT](#halt) runs the `HALT` again, as `HALT` leaves `IP` on itself, so it stays idle. On the running core (`SELF`), `WAKE` only ends the `WAIT` that an interrupt handler interrupted.

A running core with no `WAIT` to end has its notify flag (`N`) set instead, so its next `WAIT` ends at once. A core that asks for something and then `WAIT`s for the answer gets it, even if the `WAKE` comes before the `WAIT` starts. As a `WAIT` can also end early from a `WAKE` meant for an earlier request, a core checks that what it waited for happened, and `WAIT`s again if not.

| Opcode | Variant       | Cycles |
| :----: | ------------- | :----: |
| `0x8D` | `WAKE <0..7>` |   4    |
| `0x8D` | `WAKE R2`     |   4    |
| `0x8D` | `WAKE SELF`   |   5    |

#### CLRN

| Cycles |  Z  |  S  |  C  |  O  |
| :----: | :-: | :-: | :-: | :-: |
|   3    |  -  |  -  |  -  |  X  |

Clears the notify flag (`N`), which a [WAKE](#wake) sets on a running core, so the next [WAIT](#wait) waits, even if a `WAKE` came before. A program can't count on `N` being clear when it starts, as [RST](#rst) sets it on a running core.

`CLRN` is a `WAIT` of no cycles, so its flags are `WAIT`'s: it sets `O` if `N` was set, so a program can tell that a `WAKE` came. In an interrupt handler that interrupted a `WAIT`, it fails as `WAIT` does, setting `O` and leaving `N` as it was. Otherwise, `O` is cleared.

| Opcode | Variant | Cycles |
| :----: | ------- | :----: |
| `0x8E` | `CLRN`  |   3    |
