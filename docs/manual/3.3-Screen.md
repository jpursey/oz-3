# Screen

A page of memory holding character cells and control words, which the screen shows. Cores read and write the page through its bank, as any memory, with the bank's lock and cycles.

The screen **refreshes** at a fixed rate (`refresh_hz` times a second): it takes what is in its page as the picture, and the host shows that picture until the next refresh. So a program can change many parts of the screen between two refreshes and have them all appear at once.

### Wiring and settings

The screen is wired to one page of a bank, and one interrupt line on the cores it is connected to, and has no port (see [Wiring and settings](3-Devices.md#wiring-and-settings)). Its page is its own, so it is not RAM.

| Setting         | Default                                           | What                                                                                     |
| --------------- | ------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `columns`       | 80                                                | 1 to 132                                                                                 |
| `rows`          | 24                                                | 1 to 64, with at most 4080 cells                                                         |
| `refresh_hz`    | 30                                                | Refreshes a second                                                                       |
| `slow_blink_hz` | 1                                                 | The slow blink, at least 1 and at most half of `refresh_hz`                              |
| `fast_blink_hz` | 4                                                 | The fast blink, at least 1 and at most half of `refresh_hz`                              |
| `characters`    | [The built-in one](#the-built-in-character-set)   | The character set at power on: 2560 words, laid out as the character set window has them |

### Addresses

Addresses are the screen's own, from the start of its page, wherever the page is.

| Address        | Word                                                          |
| -------------- | ------------------------------------------------------------- |
| 0 to cells - 1 | The cells, row by row                                         |
| up to FEFh     | Reserved: reads 0, and writes are ignored                     |
| FF0h           | Columns (read only)                                           |
| FF1h           | Rows (read only)                                              |
| FF2h           | Frame counter (read only): refreshes since power on, wrapping |
| FF3h           | Scroll column: the column of cells shown at the left          |
| FF4h           | Scroll row: the row of cells shown at the top                 |
| FF5h           | Cursor column                                                 |
| FF6h           | Cursor row                                                    |
| FF7h           | Cursor: its mode and style                                    |
| FF8h           | Fill: the cell a column or row is filled with                 |
| FF9h           | Fill column: fills a column as it is written                  |
| FFAh           | Fill row: fills a row as it is written                        |
| FFBh           | Character set window: bit 0                                   |
| FFCh           | First compact row                                             |
| FFDh           | Compact rows: how many                                        |
| FFEh to FFFh   | Reserved: reads 0, and writes are ignored                     |

* Writes to the read-only words are ignored. So only the cells and the control words a program sets take writes: the words after the cells are reserved, however small the screen.
* **The size** is at most 132 columns and 64 rows, and at most 4080 cells (FF0h), so the cells end before the control words: up to 80 by 51, or 132 by 30. The control words are at the end of the page, so a program finds them at the same address whatever the size.
* **At power on** the page is all 0, apart from the read-only words: a blank screen, the cursor off at the top left, no compact rows, and the character set window closed.

### Cells

Each cell is one word. The low byte is the character, and the high byte its attributes, so a plain character (`'A'`, `0041h`) shows with none.

| Bit   | Attribute                                                     |
| ----- | ------------------------------------------------------------- |
| 0100h | Inverse                                                       |
| 0200h | Half intensity                                                |
| 0400h | Blink                                                         |
| 0800h | Alternate character set: the character is one of a second 256 |
| 1000h | Line on the top edge                                          |
| 2000h | Line on the bottom edge (an underline)                        |
| 4000h | Line on the left edge                                         |
| 8000h | Line on the right edge                                        |

* **Lines** light every pixel on one edge of the cell, for drawing tables and boxes, not only underlines. Two neighboring cells' lines on their shared edge make a line twice as thick. As pixels are twice as tall as they are wide, a top or bottom line is twice as thick as a left or right one.
* **Inverse** swaps the cell's lit and unlit pixels, and lines are drawn after it, so a line always shows.
* **Blink**, in its off phase, draws the whole cell off. So an inverse, blinking cell is a flashing block.

### Scrolling and filling

* **The scroll row** is the row of cells shown at the top of the screen, taken modulo the rows: the row shown below it is `scroll + 1`, wrapping at the last row. So scrolling the whole screen up or down is one write.
* **The scroll column** is the same across: the column of cells shown at the left of the screen, taken modulo the columns, so the column shown right of it is `scroll + 1`, wrapping at the last column. Each row wraps within itself, so scrolling the whole screen left or right is one write too. The two scrolls apply together.
* **Fill column and fill row:** writing a column number to fill column, or a row number to fill row, fills that column or row with the fill word, as the write happens. Each is a screen position, as shown (after the scroll), and one outside the screen fills nothing. Both read 0.
* So a terminal's line feed on the bottom row is two writes: add one to the scroll row, then fill row `rows - 1` with spaces. Scrolling a wide picture left a column is the same: add one to the scroll column, then fill column `columns - 1`. Clearing the whole screen is one write a row.

### Cursor

The cursor is at its column and row, which are screen positions, as shown (after the scroll). A cursor outside the screen is off. The cursor word is a mode, ORed with a style, and its other bits are reserved:

| Mode       | Value | Style     | Value | Draws                        |
| ---------- | ----- | --------- | ----- | ---------------------------- |
| Off        | 0     | Block     | 0     | Every pixel of the cell lit  |
| On         | 1     | Inverse   | 4     | The cell's pixels inverted   |
| Slow blink | 2     | Underline | 8     | The bottom row of pixels lit |
| Fast blink | 3     | Left edge | 0Ch   | The leftmost column lit      |

The cursor is drawn over its cell, at the cell's brightness. A blinking cursor isn't drawn in its off phase.

### Refreshes and blinking

* **Refresh `n`** is at cycle `n * clock / refresh_hz`, so the schedule doesn't drift where a refresh isn't a whole number of cycles (33,333⅓ at 30 Hz and 1 MHz).
* At a refresh, the screen takes its bank's lock, adds one to the frame counter, takes its page as the picture, and releases the lock, all in one cycle, with no cycles of its own. It never sees half of a core's write, and waits only while a core holds the bank. Then it raises its interrupt, like a vertical blank interrupt.
* A refresh that waited for the bank is granted it as the core releases it, so a core asking for the bank again in that cycle (as the next instruction's fetch does) waits a cycle for the refresh.
* Refreshes are on a fixed schedule: one that waited for the lock doesn't delay the next.
* **The frame counter** lets a program wait for a refresh by watching it change, and then draw in the time until the next one. The interrupt does the same for a program that would rather be told.
* **Blinking** is by the frame counter, so a program can time itself to it. The slow blink (the blink attribute, and the slow blink cursor) is `slow_blink_hz` times a second (once by default), and the fast blink `fast_blink_hz` times (four by default). A blink at `blink_hz` is on while `frames * 2 * blink_hz / refresh_hz` is even, where `frames` is the frame counter, so the picture a program sees the frame counter for is the one drawn with it. At 30 Hz, the slow blink is on for frames 0 to 14, off for 15 to 29, and so on.

### Pixels

The screen draws each cell from a **glyph** of 8 by 10 pixels, each twice as tall as it is wide, so an 80 by 24 screen is 640 by 480 square units. Each pixel is off, dim, or bright: a glyph's lit pixels are bright, or dim with half intensity.

### Character set

The screen draws characters from its own **character set**, which a program can redefine, to make its own graphics and animate them.

* There are 512 glyphs: the first 256 for cells without the alternate bit, and the second 256 for cells with it.
* A glyph is 10 rows of one byte each, with bit 7 the leftmost pixel, packed two rows to a word, the high byte first: 5 words a glyph. Glyph `n` (0 to 511) is at `n * 5`, so the whole character set is 2560 words, from 0 to 9FFh.
* **The character set window:** while bit 0 of FFBh is set, the character set takes the cells' place for writes: writes to addresses 0 to 9FFh go to the character set, whatever the screen's size, and writes to the cells from A00h are ignored. Reads still read the cells, so the character set can't be read back: it is write only. The control words are as they always are, and filling a column or row still fills the cells.
* A changed glyph shows at the next refresh, like everything else, so a program can change glyphs between refreshes to animate them.

### Compact rows

A band of **compact rows** packs rows 8 pixels apart rather than 10, for games and other drawing tricks. Glyphs don't change: a compact row's bottom two pixel rows overlap the next row's top two.

* The band is the screen rows from the first compact row (FFCh), as many as the compact rows word (FFDh) says. They are screen positions, so the band stays put as the cells scroll through it. Rows of the band outside the screen are ignored, and a count of 0 is no band. Making every row compact is a band from 0 of `rows`.
* Where pixels overlap, each is the brighter of the two, as on a phosphor.
* A compact row at the bottom of the screen has nothing below it, so it is drawn whole.

### The built-in character set

At power on, unless `characters` gives one of its own, the character set is the built-in one:

| Characters | Glyphs                                        |
| ---------- | --------------------------------------------- |
| 00h to 1Fh | Block and line graphics                       |
| 20h to 7Eh | ASCII                                         |
| 7Fh        | A hatch                                       |
| 80h to BFh | Sextants: 80h plus the sixths lit (see below) |
| C0h to CAh | Single lines: ─ │ ┌ ┐ └ ┘ ├ ┤ ┬ ┴ ┼           |
| CBh to D5h | Double lines: ═ ║ ╔ ╗ ╚ ╝ ╠ ╣ ╦ ╩ ╬           |
| D6h to D9h | Half lines: ╴ ╵ ╶ ╷                           |
| DAh to DDh | Rounded corners: ╭ ╮ ╯ ╰                      |
| DEh to E0h | Shades: ░ ▒ ▓                                 |
| E1h, E2h   | Halves: ▀ ▄                                   |
| E3h to E5h | Diagonals: ╱ ╲ ╳                              |
| E6h to E9h | Triangles: ◢ ◣ ◤ ◥                          |
| EAh to EDh | Arrows: ← ↑ → ↓                               |
| EEh to F1h | Suits: ♠ ♥ ♦ ♣                                |
| F2h to FFh | Symbols: • ● ○ ■ □ ✓ × ÷ ± ° £ ♪ ☺ ↕          |
| 100h–1FFh  | The alternates: the same as 00h to FFh        |

* The screen draws whatever is in a cell, so the control characters have glyphs like any other. A program that prints text handles control characters before it writes cells.
* Text is drawn in the left 6 or 7 pixels of the cell, from pixel row 1, with descenders in rows 8 and 9.
* **Sextants** divide the cell into 2 columns of 4 pixels, and rows of 3, 4, and 3 pixels, so each sixth is nearly square: 160 by 72 of them on an 80 by 24 screen. Bit 0 of the character is the top left sixth, bit 1 the top right, and so on to bit 5, the bottom right. 80h is blank, and BFh full.
* **Lines** run through the middle of the cell, so they join from cell to cell: a single line is 2 pixels wide (columns 3 and 4) and 1 tall (row 4), and a double line two of them (columns 1, 2, 5, and 6, and rows 3 and 5).
* The alternates are a copy, so the alternate attribute changes nothing until a program redefines them. A program can take the alternates for its own graphics without losing a character of the font.
