# Power Control

A port that a program writes to shut the machine down, with an exit code, or to restart it.

### Wiring and settings

The power control is wired to one port, and has no interrupt, memory, or settings (see [Wiring and settings](3-Devices.md#wiring-and-settings)).

### Commands

A program writes the **command** to port word 0, and for a shutdown, the **exit code** to word 1, as a signed word. One `OUT.ID` writes both, with the exit code in the high word. With the power control on port 0:

```
OUT.ID 0, 0FFFF0001h   ; Shut down, with exit code -1
HALT
```

| Command | What                                                    |
| ------- | ------------------------------------------------------- |
| 1       | Shut down: power off, with the exit code                |
| 2       | Restart: power off and on again, ignoring the exit code |
| Other   | Reserved: does nothing                                  |

* **Taking:** The power control takes what is written as soon as the port's status is set (by `OUT`, `OUTS`, or `OUTR`), the cycle after the store, and clears both words and the status. So a command written later as a word, such as with `OUT.IW 0, 1`, shuts down with exit code 0, rather than an earlier write's.
* **The host acts on it:** The power control asks the host application to shut the machine down or restart it, and the host does so when it next can, which is not at once. The machine runs on meanwhile, so a program halts after writing the command, or loops, rather than counting on the next instruction not running.
* **Every command reaches the host:** The power control passes on each shutdown and restart a program asks for, however many there are, and the host decides what to do with them, such as acting on the first, or the last.
* **The exit code** is the host's to use as it likes, such as by exiting with it.
* **Reading** the port isn't the power control's business: a core that reads it gets whatever is there, and clears the status, which loses a command not yet taken.
